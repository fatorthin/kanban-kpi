# 📑 KPI App

## 1. Project Overview

Building an internal task management platform for a tax consulting firm using the **TALL Stack (Custom UI)**. The focus is on workload standardization through a **Task Reference Library**, a responsive **Kanban Board**, and performance transparency via a **KPI Load Point System**.

## 2. Technical Stack Specification

- **Backend:** Laravel 11 & PHP 8.3+.
- **Frontend UI:** Tailwind CSS (Strictly guided by the user's specific UI reference `design.md` file).
- **Reactivity:** Livewire 3 (SPA Mode with Wire-Navigate).
- **Interactivity & Drag-and-Drop:** Alpine.js (SortableJS).
- **Real-time:** Laravel Reverb (WebSockets).
- **Roles & Logs:** Spatie Laravel Permission & Spatie Activitylog.

## 3. Database Schema Blueprint

The database is designed as a highly integrated relational system. Below is the table structure, data types, and relationships.

### A. Master Data & Authentication

**1. `divisions`** (Company Divisions)

- `id` (PK, BigInt)
- `name` (String) - _Ex: Tax, Accounting, HRD, Finance._
- `timestamps`

**2. `users`** (Employees/Management)

- `id` (PK, BigInt)
- `name`, `email`, `password` (String)
- `division_id` (FK -> divisions.id)
- `base_point_rate` (Decimal/Integer) - _Currency value (Rupiah) per 1 KPI Load Point._
- `fcm_token` (String, Nullable) - _For push notifications._
- `timestamps`, `softDeletes`

**3. `clients`** (Consultant's Clients)

- `id` (PK, BigInt)
- `name` (String)
- `code` (String, Unique)
- `grade` (Enum: A, B, C, D, E, F) - _Determines default difficulty points._
- `timestamps`, `softDeletes`

**4. `task_references`** (Task Library / Point Master)

- `id` (PK, BigInt)
- `title` (String) - _Ex: "Annual Corporate Tax Return"._
- `description` (Text) - _Contains standard operating procedures (SOP)._
- `task_type` (Enum: Client, Internal)
- `default_difficulty_points` (Integer) - _Standard points for this task._
- `timestamps`

### B. Transactional Data (Core System)

**5. `tasks`** (Actual Tasks / Kanban Cards)

- `id` (PK, BigInt)
- `task_reference_id` (FK -> task_references.id, Nullable)
- `client_id` (FK -> clients.id, Nullable)
- `pic_id` (FK -> users.id) - _Current staff assigned to the task._
- `original_pic_id` (FK -> users.id, Nullable) - _The first person assigned, used for penalty logic._
- `manager_id` (FK -> users.id) - _Manager who assigned/reviews the task._
- `title` (String)
- `description` (Text, Nullable)
- `task_type` (Enum: Client, Internal)
- `status` (Enum: New, In_Progress, Review, Revision, Completed)
- `previous_status` (Enum, Nullable) - _For the Kanban UNDO feature._
- `is_takeover` (Boolean, Default: false)
- `difficulty_points` (Integer) - _Copied from reference but can be overridden by the manager._
- `revision_count` (Integer, Default: 0)
- `deadline` (DateTime)
- `completed_at` (DateTime, Nullable)
- `timestamps`, `softDeletes`

**6. `recurring_tasks`** (Automated Scheduler Templates)

- `id` (PK, BigInt)
- `task_reference_id` (FK -> task_references.id)
- `client_id` (FK -> clients.id, Nullable)
- `pic_id` (FK -> users.id)
- `manager_id` (FK -> users.id)
- `frequency` (Enum: Daily, Weekly, Monthly, Yearly)
- `day_of_month` (Integer, Nullable) - _Ex: The 5th of every month._
- `is_active` (Boolean, Default: true)
- `timestamps`

### C. Communication & Tracking

**7. `task_messages`** (Per-Task Chat)

- `id` (PK, BigInt)
- `task_id` (FK -> tasks.id)
- `user_id` (FK -> users.id) - _Sender._
- `message` (Text)
- `attachment_path` (String, Nullable)
- `timestamps`

**8. `message_read_statuses`** (Read Receipts Pivot)

- `id` (PK, BigInt)
- `message_id` (FK -> task_messages.id)
- `user_id` (FK -> users.id) - _Who read the message._
- `read_at` (Timestamp)

**9. `kpi_reports`** (Monthly Recaps)

- `id` (PK, BigInt)
- `user_id` (FK -> users.id)
- `month` (Integer)
- `year` (Integer)
- `total_load_points` (Integer)
- `productivity_score` (Decimal)
- `quality_score` (Decimal)
- `timeliness_score` (Decimal)
- `final_kpi_score` (Decimal) - _Final NAK Score (0-100)._
- `total_incentive` (Decimal) - _Calculated currency payout._
- `timestamps`

_(Note: The `roles`, `permissions`, and `activity_log` tables will be automatically generated by the Spatie packages)._

## 7. Business Logic Details (Workflow System)

### A. Task Library Auto-Fill

When a Manager creates a new task (`tasks.create`), if they select a "Task Reference" from the dropdown, the `title`, `description`, and `difficulty_points` fields will auto-fill. The Manager can edit these pre-filled values before saving.

### B. Kanban Undo Logic

If a card is dragged and its status changes, the UI displays a _Toast_ for 10 seconds. If the `Undo` button is clicked, the system triggers a Livewire function to revert the `status` to the value stored in the `previous_status` column.

### C. Chat & Read Receipts Logic

When a staff/manager opens the Slide-over chat component for a task, the system automatically runs an `Insert/Update` on the `message_read_statuses` table for all messages in that `task_id` where the sender is NOT the currently logged-in user. Reverb will broadcast this event to change the sender's UI status to "Seen".

### D. KPI Calculation (Cron Job / End of Month)

On the 1st of every month, the system calculates the following:

- **S_prod:** `(Completed Points / Total Assigned Points) * 100`
- **S_qual:** `100 - (Revision Count * 15)`
- **S_time:** Compare `completed_at` vs `deadline`. If late = penalty -10/day.
- **NAK (Final Score):** `(S_prod * 0.4) + (S_qual * 0.3) + (S_time * 0.3)`
- **Incentive:** `NAK * adjusted_total_points * base_point_rate`
  All results are saved into the `kpi_reports` table.

### E. Task Takeover System (Penalty & Reward)

To ensure task completion and accountability, the system implements a takeover mechanism:

1.  **Trigger**: A task becomes "Takeover Eligible" if it remains incomplete **24 hours after the deadline** or if a **Manager/Director manually triggers** a reassignment due to stagnation.
2.  **Reward (The "Hero")**:
    - The new PIC who takes over and completes the task receives **100% of the Difficulty Points** plus a **20% "Rescue Bonus"**.
    - *Calculation:* `Final Points = difficulty_points * 1.2`.
3.  **Punishment (The "Original PIC")**:
    - The original PIC incurs a **Point Penalty** equal to **50% of the task's original Difficulty Points**.
    - This penalty is deducted from their `total_load_points` for the month.
4.  **Audit Trail**: Every takeover event must be logged in `activity_log`, capturing the `original_pic_id`, `new_pic_id`, and the `reason` (Deadline Breached / Manager Intervention).
